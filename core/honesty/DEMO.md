## What this proves (architecture §2.6)

- The agent cannot edit the judge, its inputs, or its verdicts: the pipeline builds the
  `JudgeInput` from the turn report, judges run against a deep-frozen copy, and verdicts
  are stored as first-write-wins outcome records before being attached as evidence.
- A FAIL verdict is data the user sees (`report.honesty.failedVerdicts`), not an exception
  the loop hides — (iii) shows the failure present in the turn output.
- A judge *infrastructure* error is a typed stream error, distinct from a FAIL verdict
  (covered in `honesty/test/wiring.test.ts`: `JudgeNotFound` on the error channel).
- Verdicts are deterministic: `verdictId` is a content hash over (judge id, version, input);
  `ranAt` is stamped by the runner after the verdict is computed. Re-running the pipeline
  on the same turn data yields identical verdictIds (tested).
